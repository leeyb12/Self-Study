## 이클립스에서 자바 프로젝트 생성 및 설정
> "이클립스에서 자바 소스 코드를 작성하려면 먼저 프로젝트를 생성해야 하며, 프로젝트 생성 과정에서 JDK 버전 선택과 프로젝트 레이아웃 등을 설정할 수 있다."

### 1. 자바 프로젝트 생성 절차
- 패키지 익스플로러에서 <mark>Create Java Project</mark> 클릭 또는 <mark>File</mark> 메뉴 → <mark>New</mark> → <mark>Java Project</mark> 선택
- 프로젝트 이름 입력 (예: <mark>this_is_java</mark>)
- 기본 저장 위치는 워크스페이스 내부 (<mark>Use default location</mark>)
- JRE(즉, Java 실행환경, Java Runtime Environment) 버전 선택 가능
- 프로젝트 레이아웃: 소스 폴더와 컴파일된 바이트코드 폴더를 분리하는 옵션 선택 권장 (폴더 분리하여 관리)
- 모듈 관련 옵션은 초반에 체크 해제 권장 (추후 학습)

### 2. JDK 및 JRE 버전 설정 이해 
| 옵션 번호 | 설명 | 특징 및 사용 시점 | 
|-----------|------|-------------------|
| 1 | Java SE 스펙 기준으로 설정 (<mark>Use execution environment JRE</mark>) | JDK 빌드 번호 무시, 예: Java 17이면 17.x.x 전체 빌드 번호 무관 |
| 2 | 특정 JRE 선택 (Alternate JRE) | 직접 설치한 JDK 경로를 등록해 사용 가능, 프로젝트별 JDK 고정 가능 | 
| 3 | 이클립스 기본 JRE 사용 (Workspace default JRE) | 이클립스 내 기본 JRE 설정에 따라 컴파일 및 실행 환경 결정 | 

- JDK: Java Development Kit (개발 도구 모음)
- JRE: Java Runtime Environment (실행 환경)
- Java SE Spec (Java SE 스펙): 자바 기능 표준 규격

### 3. JDK 추가 및 변경 방법
- <mark>Window</mark> -> <mark>Preferences</mark> -> <mark>Java</mark> -> <mark>Installed JREs</mark> 선택
- <mark>Add</mark> 버튼 클릭 후 JDK 설치 경로 지정 (예: <mark>C:\Program Files\Java\jdk-17.0.4</mark>)
- 추가된 JDK를 프로젝트에 적용 가능
- 프로젝트 생성 시 두 번째 옵션에서 직접 선택 가능
- 이클립스 기본 JRE 변경 시 <mark>Apply and Close</mark> 클릭하여 반영

### 4. JDK, JRE, Java SE 스펙 용어 정리
| 용어 | 의미 및 맥락 |
|------|--------------|
| Java (자바) | 프로그래밍 언어 및 플랫폼 전체를 의미하며, 일반적으로 개발 시 '자바'라고 부름 |
| JDK | Java Development Kit, 자바 개발 도구 모음 (컴파일과 개발에 필요한 도구 포함) |
| JRE | Java Runtime Environment, 자바 실행 환경 (컴파일된 프로그램 실행에 필요한 환경) |
| Java SE Spec | Java Standard Edition Specification, 자바 표준 플랫폼 규격 (기능적 사양과 API 명세) |
| Java Runtime (JRE) | 실제 실행 환경으로서 프로그램이 동작하는 환경을 의미하며, JDK에 포함되어 있음 |

- 개발자가 "자바"라고 말할 때는 흔히 JDK를 뜻함
- 실행 환경에 집중할 때는 JRE(제알) 또는 Java Runtime이라고 부름
- 버전 관리는 Java SE 스펙 기준으로 구분하며, JDK는 이를 구현한 제품임

### 5. 프로젝트 삭제 및 파일 시스템 영향
- 프로젝트 이름 우클릭 -> <mark>Delete</mark> 선택
- 삭제 창에서 파일 시스템 내 실제 폴더 삭제 여부 선택 가능
  - 체크 해제 시: 프로젝트는 이클립스 패키지 익스플로러에서만 사라지고 실제 파일은 남음
  - 체크 시: 프로젝트 폴더 및 파일도 완전히 삭제됨

### 6. 프로젝트 생성 시 인코딩 설정 변경 (윈도우 환경)
- 기본 텍스트 인코딩: 윈도우는 기본적으로 <mark>MS949</mark> (cp949), MacOS는 <mark>UTF-8</mark>
- 대부분의 개발 소스는 <mark>UTF-8</mark> 인코딩 사용 권장
- 인코딩 변경 방법
  - <mark>Window</mark> -> <mark>Preferences</mark> -> <mark>General</mark> -> <mark>Workspace</mark>
  - <mark>Text file encoding</mark> 항목에서 <mark>MS949</mark> -> <mark>UTF-8</mark>로 변경
  - 적용 후 이클립스 재시작 권장

### 7. 프로젝트 레이아웃과 소스 관리
- 프로젝트 레이아웃은 소스 파일과 컴파일된 <mark>.class</mark> 파일을 별도의 폴더를 분리하여 관리하는 것이 일반적임
- 소스 폴더(<mark>src</mark>)와 출력 폴더(<mark>bin</mark> 또는 <mark>target/classes</mark>)를 분리함으로써 개발과 빌드 관리가 용이

이클립스에서 자바 프로젝트 생성은 프로젝트 이름 지정, JRE/JDK 버전 선택, 프로젝트 레이아웃 설정, 인코딩 관리 등 여러 단계가 체계적으로 연결되어 있으며, 각 설정은 개발 환경과 실행 환경에 직결된다. JDK와 JRE는 개발과 실행을 구분하는 개념으로 혼동하기 쉬우나 각각의 역할과 적용 범위를 명확히 이해하는 것이 중요하다. 또한, 프로젝트 삭제 시 파일 시스템상 실제 데이터의 유지 여부를 신중히 결정해야 하며, 텍스트 인코딩 설정은 소스 코드의 문자 인식에 큰 영향을 미쳐 반드시 올바르게 설정해야 한다. 이러한 요소들이 통합되어 자바 개발의 안정성과 효율성을 보장한다.

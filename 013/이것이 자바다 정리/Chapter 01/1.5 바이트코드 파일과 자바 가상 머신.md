## 자바 소스 파일과 바이트 코드 파일 
> "자바 소스 파일은 텍스트 파일로, 확장명이 <mark>.java</mark>이다. 작성한 소스 파일을 컴파일하면 바이트 코드 파일이 생성된다."
- 자바 소스 파일: 확정자 <mark>.java</mark>
- 작성 방법: 텍스트 에디터로 작성 가능
- 컴파일 명령어: <mark>javac</mark> (Java Compiler 약자)
- 컴파일 결과: 바이트 코드 파일 <mark>.class</mark> 생성
- 운영체제 독립성: 윈도우, 맥 OS, 리눅스 모두 동일한 <mark>.class</mark> 파일 생성

| 구분 | 설명 | 예시 파일명 |
|------|------|-------------|
| 소스 파일 | 자바 코드 작성, 텍스트 파일 | <mark>Hello.java</mark> |
| 컴파일러 | <mark>javac</mark> 명령어 사용 | <mark>javac Hello.java</mark> |
| 바이트 코드 파일 | 컴퓨터가 직접 실행할 수 없는 중간 코드 | <mark>Hello.class</mark> |

## 자바 가상 머신(JVM)의 역할과 구조
> "바이트 코드 파일은 완전한 기계어가 아니므로, 이를 실행 가능한 기계어로 변환하는 역할을 자바 가상 머신(JVM)이 수행한다."
- 바이트 코드 파일: 중간 코드로, 운영체제나 하드웨어에 독립적임
- JVM(Java Virtual Machine): 바이트 코드를 해당 운영체제에 맞는 기계어로 변역하여 실행
- 실행 명령어: <mark>java</mark> 명령어로 JVM 구동
- 운영체제별 JVM: 윈도우용 JVM, 맥 OS용 JVM, 리눅스용 JVM 등이 각각 다르게 존재
- JDK 설치: 운영체제별로 맞는 JDK 설치 시 해당 운영체제용 JVM도 함께 설치됨

| 구성 요소 | 역할 및 특징 |
|-----------|--------------|
| 바이트 코드 파일 | 소스 컴파일 결과, OS 독립적 |
| JVM | 바이트 코드를 OS에 맞는 기계어로 변환 및 실행 |
| <mark>java</mark> 명령어 | JVM을 구동시키는 명령어, OS별로 동일하게 사용 가능 |

## 운영체제와 자바 실행의 관계
- 바이트 코드 파일은 동일하지만, JVM은 운영체제별로 다르게 구현되어 있음
- 예를 들어,
  - 윈도우용 JVM: 윈도우에서 이해할 수 있는 기계어로 번역
  - 맥 OS용 JVM: 맥 OS에서 이해할 수 있는 기계어로 번역
- 따라서 JDK를 설치할 때 운영체제별 맞춤버전을 설치해야 함
- <mark>java</mark> 명령어는 운영체제에 맞는 JVM을 자동으로 실행하여 바이트 코드를 실행함
- 결과적으로 한 번 작성하고 컴파일한 <mark>.class</mark> 파일을 여러 운영체제에서 실행 가능

| 운영 체제 | JDK 설치 파일 종류 | JVM 역할 |
|-----------|--------------------|----------|
| 윈도우 | 윈도우용 JDK | 윈도우 기계어로 바이트 코드 변환 |
| 맥 OS | 맥 OS용 JDK | 맥 OS 기계어로 바이트 코드 변환 |
| 리눅스 | 리눅스용 JDK | 리눅스 기계어로 바이트 코드 변환 |

## 자바 개발과 실행 흐름 정리
| 단계 | 설명 | 명령어/파일 |
|------|------|-------------|
| 1. 소스 작성 | 자바 코드 작성, 텍스트 파일 생성 | <mark>Hello.java</mark> |
| 2. 컴파일 | <mark>javac</mark> 명령어로 컴파일, 바이트 코드 생성 | <mark>javac Hello.java</mark> -> <mark>Hello.class</mark> | 
| 3. 실행 | <mark>java</mark> 명령어로 JVM 구동, 바이트 코드를 기계어로 번역 후 실행 | <mark>java Hello</mark> |

- <mark>Hello.java</mark> -> 컴파일 -> <mark>Hello.class</mark> -> JVM 실행 -> 기계어로 번역 -> 실행 결과 출력
- 운영체제와 무관하게 <mark>.class</mark> 파일은 동일하며, JVM이 OS별로 맞게 번역 수행
- 개발 환경과 실행 환경이 다를 수 있어도 코드 수정 없이 실행 가능

## 비유를 통한 이해: 자바 코드와 JVM 관계
- 자바 소스 코드는 "외국어 원문 텍스트"와 같다. 
- 바이트 코드는 "공통 중간 언어 번역문"으로, 여러 국가에서 이해할 수 있는 형태지만 직접 읽을 수는 없다. 
- JVM은 "현지 통역사" 역할로, 이 중간 언어를 각 나라의 언어(운영체제 기계어)로 즉시 번역해준다. 
- 이 덕분에 하나의 원문(자바 코드)을 여러 나라(운영체제)에서 이해할 수 있는 현지 언어로 실행 가능하다. 

자바의 소스 파일은 텍스트로 작성되어 컴파일 시 바이트 코드로 변환되고, 이 바이트 코드는 JVM을 통해 각 운영체제에 맞는 기계어로 번역되어 실행된다. 이 과정에서 운영체제별 JVM이 다르게 구현되어야 하며, <mark>java</mark> 명령어는 운영체제에 따른 JVM을 구동하여 실행을 담당한다. 따라서 자바는 한번 컴파일하면 여러 운영체제에서 동일한 바이트 코드를 재활용할 수 있어 뛰어난 이식성을 가진다.

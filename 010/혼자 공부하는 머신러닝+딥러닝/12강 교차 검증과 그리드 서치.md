## 12강 교차 검증과 그리드 서치
### 데이터셋 분할과 검증 세트
> "테스트 세트는 모델 성능을 최종 평가하기 위한 데이터이며, 모델 훈련과 튜닝 과정에서는 사용해서는 안 된다."
- 전체 데이터셋을 다음 세 가지로 분할 
- 테스트 세트를 반복적으로 사용해 매개변수를 튜닝하면 테스트 세트에 과적합되어 실제 성능 예측이 어려워짐
- 검증 세트는 훈련 세트와 테스트 세트 사이의 중간 역할로, 하이퍼파라미터 튜닝에 활용
- 데이터가 크면 검증/테스트 세트 비율을 줄여도 무방 (예: 10%, 5%)
- <mark>train_test_split</mark> 함수를 두 번 사용하여 간단히 3분할 구현 가능 (예: 처음 80% 뽑고, 그 안에서 다시 30%를 검증 세트로 분리)

### 교차 검증 (Cross-Validation)
> "교차 검증은 데이터를 여러 폴드(fold)로 나누어 반복적으로 훈련과 평가를 수행하여 안정적인 성능 평가를 제공한다."
- 테스트 세트는 분리한 상태에서, 훈련+검증 데이터 전체를 여러 폴드(보통 5개)로 나눔
- 각 폴드가 검증 세트 역할을 번갈아 가며 수행
  - 예) 3폴드일 경우
    - 폴드1 + 폴드2 훈련, 폴드3 검증
    - 폴드1 + 폴드3 훈련, 폴드2 검증
    - 폴드2 + 폴드3 훈련, 폴드1 검증
- 모든 샘플이 한 번은 검증 세트로 사용되므로 편향 낮음
- 각 폴드 점수를 평균하여 더 안정적인 평가값 산출
- 데이터셋이 작을 때 특히 유용 

| 장점 | 설명 |
|------|------|
| 데이터 최대 활용 | 모든 데이터가 훈련과 검증에 고루 사용됨 |
| 안정적 평가 | 이상치나 편차에 덜 민감한 평균 성능 산출 |
| 과적합 점검 | 과적합 여부 검증 세트에서 반복적으로 확인 가능 |

- scikit-learn의 <mark>cross_val_score</mark> 함수로 쉽게 구현 가능
- 기본 5폴드 사용, <mark>cv</mark> 매개변수로 폴드 수 조절 가능 (예: 10폴드)
- 모델마다 적합한 분할기 사용
  - 회귀: <mark>KFold</mark>
  - 분류: <mark>StratifiedKFold</mark> (클래스 비율 균등 분배)

### 하이퍼파라미터 튜닝과 그리드 서치 (Grid Search CV)
> "그리드 서치는 여러 하이퍼파라미터 조합을 체계적으로 탐색하여 최적의 모델 설정을 찾는다."
- 결정트리의 대표적 하이퍼파라미터 예시
- 그리드 서치는 모든 파라미터 값의 가능한 조합을 생성하여 교차 검증 수행
- 단일 파라미터 순차 최적화 불가: 서로 영향이 있으므로 모든 조합을 동시에 탐색해야 함
- scikit-learn의 <mark>GridSearchCV</mark> 클래스로 구현
- <mark>n_jobs=-1</mark> 설정 시 CPU 코어를 모두 활용해 병렬 처리 속도 향상
- 최적 파라미터는 <mark>best_params_</mark> 속성에서 확인 가능
- 최적 모델은 <mark>best_estimator_</mark>에 저장

| 하이퍼파라미터 조합 개수 계산 예시 | 개수 |
|------------------------------------|------|
| <mark>max_depth</mark>: 5~20 (16개) | 16 |
| <mark>min_impurity_decrease</mark>: 0.001~0.005 (5개) | 5 |
| <mark>min_samples_split</mark>: 2~100 (10개) | 10 |
| 총 조합 수 | 16 x 5 x 10 = 800개 |
| 5폴드 교차검증 시 모델 수 | 800 x 5 = 4,000개 | 

- 조합 수가 많아지면 계산 비용 급증 (시간, 메모리 등)

### 랜덤 서치 (Randomized Search CV)
> "랜덤 서치는 파라미터 공간에서 확률 분포를 지정해 무작위로 조합을 샘플링하여 효율적으로 탐색한다."
- 그리드 서치의 조합 폭발 문제를 완화하기 위한 방법
- 각 하이퍼파라미터에 대해 확률 분포를 지정하고, 지정된 횟수만큼 무작위 샘플링
- <mark>RandomizedSearchCV</mark> 클래스 사용
- 검색 횟수(<mark>n_iter</mark>)를 지정해 계산 비용 조절 가능
- 예시 확률 분포 함수 (SciPy stats 모듈 활용)
- 예시 파라미터 설정
- 랜덤 서치는 일정량의 무작위 탐색만 진행해 빠르고 효율적이지만, 최적 솔루션을 놓칠 수도 있음
- 결과는 <mark>best_params_</mark>, <mark>best_estimator_</mark>에 저장
- 테스트 세트 점수와 교차 검증 점수 간 큰 차이 없이 실전 성능 예측 가능

### 실습 및 구현 팁
| 작업 내용 | 방법 및 도구 |
|-----------|--------------|
| 데이터 3분할 | <mark>train_test_split</mark> 함수 2회 호출 |
| 기본 교차 검증 | <mark>cross_val_score</mark> 함수 사용 |
| 폴드 수 조절 | <mark>cv</mark> 매개변수에 정수 입력 |
| 분류 시 클래스 균등 분할 | <mark>StratifiedKFold</mark> 사용 |
| 하이퍼파라미터 그리드 탐색 | <mark>GridSearchCV</mark> 클래스 |
| 하이퍼파라미터 랜덤 탐색 | <mark>RandomizedSearchCV</mark> 클래스, <mark>n_iter</mark> 지정 | 
| 병렬 처리 | <mark>n_jobs=-1</mark> 설정으로 CPU 코어 모두 활용 |

- 반복문을 이용해 직접 구현 가능하지만, scikit-learn 내장 함수 사용 시 코드 간결 및 안정성 확보
- CPU 코어 활용으로 연산 시간 단축 가능

### 성능 평가와 모델 선택 과정
- 모델 학습 -> 검증 세트로 하이퍼파라미터 튜닝 (과적합 여부 확인) -> 최적 하이퍼파라미터 결정
- 최종적으로 테스트 세트에서 한 번만 평가하여 실전 성능 예측
- 검증 세트 점수 > 테스트 세트 점수인 것이 정상적 (검증 세트에 맞춤)
- 테스트 세트에 반복적으로 맞추면 실제 배포 시 성능 저하 발생 가능
- 교차 검증 결과 평균 점수는 보다 신뢰할 만한 모델 성능 추정치 제공

<hr>
결정트리 모델의 다양한 하이퍼파라미터가 서로 상호의존 관계를 가진 상태에서, 교차 검증은 데이터의 작은 편차와 이상치 영향을 줄여 안정적인 검증 점수를 산출하며, 그리드 서치와 랜덤 서치를 이용한 하이퍼파라미터 탐색은 광범위한 파라미터 공간에서 효율적으로 최적의 조합을 찾아내어 모델의 일반화 성능을 극대화한다. 데이터 분할 전략과 평가 절차가 엄격히 준수될 때, 모델이 실전 환경에서 기대되는 성능과 일치하는 신뢰성 높은 예측력을 확보할 수 있다.

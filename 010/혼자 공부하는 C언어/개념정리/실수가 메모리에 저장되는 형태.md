## 실수가 메모리에 저장되는 형태
### 정수와 부동소수점 데이터 저장 방식
- 정수 변수 선언 시 메모리 4바이트(32비트) 할당
- 1바이트 = 8비트, 4바이트 = 32비트
- 초기화 전 변수는 임의 값 가짐
- 예) 정수 13을 변수 A에 대입하면 32비트 이진수로 저장
  - 13 = $2^3 + 2^2 + 2^0 = 8 + 4 + 1$ 
  - 이진수: <mark>0000 0000 0000 0000 0000 0000 0000 1101</mark>
- 음수는 2의 보수법(two's complement)으로 저장

### 부동소수점 수 저장: IEEE 754 표준
- 부동소수점 수 저장은 IEEE(Institute of Electrical and Electronics Engineers)에서 표준화
- 3가지 포맷: 단정도(single, 4바이트), 배정도(double, 8바이트), 사중정도(quad)
- 보통 double 포맷을 기본적으로 사용 (8바이트, 64비트)
- 예) 변수 B에 6.5를 저장할 때 배정도 포맷 기준
  1. 6.5를 이진수로 변환 -> $110.1_2 = 1.101_2 \times 2^2$
  2. 정규화(normalization): 소수점 앞에 1자리 비제로 숫자만 남긴 형태
  3. 세 가지 정보 추출
     - 부호 비트(sign bit): 0 (양수)
     - 지수(exponent): 2 (소수점 이동 횟수)
     - 가수(significand): 소수점 뒤 숫자 <mark>101</mark> (여기서 첫 1은 생략)
  4. 지수는 bias 1023를 더해 저장 -> 2 + 1023 = 1025
  5. 비트 배열로 저장
     - 1비트 부호
     - 11비트 지수 (1025 -> 이진수로 저장)
     - 52비트 가수 (맨 앞 1은 저장하지 않고 나머지 비트만 저장)

| 비트 구간 | 길이(bit) | 내용 |
|-----------|-----------|------|
| 부호(Sign) | 1 | 0: 양수, 1: 음수 |
| 지수(Exponent) | 11 | 지수값 + Bias(1023) |
| 가수(Significand) | 52 | 정규화된 소수점 이하 이진수 |

- 6.5 저장 시 메모리 배열 <br>
  부호 0 \| 지수 1025(이진) \| 가수 101 + 0으로 채움

### 부동소수점 수의 근사와 오차
- 6.4처럼 0.4를 2진법으로 변환하면 무한 반복 소수가 된다
- 예: 0.4 -> 0.0110 0110 0110...(무한 반복)
- 메모리 크기 제한 때문에 소수점 이하 비트가 잘리고 근사값 저장 -> 오차 발생
- 이러한 오차를 입실론 오차(epsilon error)라고 함
- 부동소수점은 정확한 표현 불가, 계산 중 오차 발생 가능
- 따라서 정확도가 필요한 계산에는 정수 타입 사용 권장
- 부동소수점은 매우 크거나 작은 수를 지수 형태로 간편히 표현하기 위해 사용

### 부동소수점 수 저장 과정 정리
| 단계 | 설명 |
|------|------|
| 1. 이진 변환 | 실수 값을 이진법으로 변환 |
| 2. 정규화 | 1.xxx × $2^n$ 형태로 변환하여 소수점 앞에 1자리만 남김 |
| 3. 부호 추출 | 양수(0), 음수(1) 결정 |
| 4. 지수 저장 | 지수에 bias(배정도: 1023) 더해 11비트로 저장 |
| 5. 가수 저장 | 정규화된 수의 소수점 이하 부분을 52비트로 저장 (맨 앞 1은 저장 안 함) |

### 실제 저장값 확인 프로그램 예시
- 6.5를 double에 저장하면 이진 표현이 정확히 일치함
- 6.4는 반복 소수 때문에 정확한 2진 표현 불가, 근사값 저장
- 디버깅용 출력은 4비트 단위로 나누어 배열된 비트 확인 가능

### 부동소수점 수 표현의 중요 포인트
- 부동소수점 저장은 부호, 지수, 가수 세 부분으로 나누어 표현
- 지수는 bias를 더해 음수 지수값도 양수로 변환 후 저장
- 첫 번째 1비트는 항상 존재하므로 저장하지 않고 공간 효율화
- 무한 반복되는 이진 소수는 메모리 한계로 인해 근사 저장 -> 오차 발생 
- 부동소수점 수는 정수보다 계산 속도가 느리고, 오차 발생 가능성 존재
- 정확한 수치 계산이 필요하면 가능하면 정수 사용 권장

<hr>
부동소수점 저장 방식은 수의 표현을 부호, 지수, 가수로 분리하고, 지수에 bias를 더하는 방식으로 음수와 양수를 함께 표현한다. 정규화(normalization)를 통해 소수점 앞에 항상 1자리 비제로 숫자를 두어 가수 부분의 효율을 극대화하며, 무한 반복 이진 소수는 근사치로 저장되어 오차가 발생한다. 이로 인해 실수 계산 시 오차가 불가피하며, 정수 연산이 더 정확하고 빠른 처리 속도를 보장한다.

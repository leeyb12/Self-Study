## 데이터 형식과 변수의 개념
> "데이터 형식은 데이터의 유형과 크기를 지정하는 것"
> "변수는 데이터를 저장할 수 있는 메모리 공간이며, 데이터 형식에 따라 유형과 크기가 정해진다."
- 데이터 형식 종류
  - 기본 데이터 형식 (primitive types)
  - 복합 데이터 형식 (composite types)
- 데이터 유형 예시: 정수, 부동소수점, 문자열, 이미지 등
- 데이터 크기: 1바이트, 2바이트 등 메모리 크기 단위
- C#의 데이터 형식 분류
  - 기본 데이터 형식: 정수형, 부동소수점형, 문자형, 논리형, 오브젝트형 등
  - 복합 데이터 형식: 기본 데이터 형식을 조합하여 만듦 (클래스, 구조체, 튜플 등)

## 정수와 부동소수점 처리
- ALU(산술논리장치): 정수 연산 담당
- FPU(부동소수점 연산장치): 소수 연산 담당
- 정수: 1, 2, 3 등 소수점 없는 숫자
- 부동소수점(floating point): 3.14, 2.718 등 소수점 숫자
  - "부동"은 소수점 위치가 변할 수 있음을 의미
  - 고정 소수점과 대비됨
    - 고정 소수점: 소수점 이하 자리수를 고정하여 표현 (예: 소수점 이하 2자리까지)
    - 부동 소수점: 유효숫자와 소수점 위치를 따로 저장 (3.14 = 314 X $10^{-2}$)
- 알고리즘 차이: 정수와 부동소수점은 덧셈, 뺄셈, 곱셈 알고리즘이 다름
- CPU 명령어: 데이터 타입에 따라 다른 명령어를 사용
- 컴파일러 역할: CPU는 데이터 타입을 스스로 판단하지 못하므로 컴파일러가 이를 지원

## 메모리 구조: 스택과 힙
| 구분 | 스택(Stack) | 힙(Heap) |
|------|-------------|----------|
| 구조 | LIFO(Last In First Out), 책 더미 형태 | 자유로운 저장 공간, 위치는 자유롭게 저장 |
| 저장 데이터 | 기본 데이터 형식 직접 저장 | 데이터의 실제 값은 힙에 저장, 스택에는 주소 저장 |
| 할당/해제 | 자동 메모리 관리, 함수 호출 시 생성/소멸 | 수동 또는 가비지 컬렉터에 의해 해제 가능 |
| 별명 | 자동 메모리 | 자유 저장소 (프리스토어) |

- 스택 예시: 변수 선언 순서대로 메모리 쌓임, 마지막에 쌓인 데이터부터 제거
- 힙 예시: 책상 위 여러 물건처럼 자유롭게 저장, 위치 추적 필요

## 값 형식(Value Type)과 참조 형식(Reference Type)
| 구분 | 값 형식 (가평식) | 참조 형식 (레퍼런스 타입) |
|------|------------------|---------------------------|
| 저장 위치 | 스택에 직접 값 저장 | 힙에 값 저장, 스택에는 힙 주소(참조) 저장 |
| 예시 | 정수, 부동소수점, 구조체 등 | 클래스, 배열, 문자열, 복합 데이터 등 |
| 메모리 관리 | 자동 (스택에서 순서대로 해제) | 가비지 컬렉터가 참조 없을 때 자동 해제 |
| 특징 | 크기가 작고 단순한 데이터에 적합 | 큰 데이터나 복잡한 구조에 적합 |

- 참조형식은 힙에 데이터를 저장해 메모리 크기가 크거나 복잡한 데이터를 처리할 수 있도록 한다.
- C#은 가비지 컬렉터(Garbage Collector)를 통해 힙 메모리를 자동 관리
- 가비지 컬렉터는 더 이상 참조되지 않는 힙 영역의 메모리를 자동으로 회수

## 박싱(Boxing)과 언박싱(Unboxing)
- 박싱(Boxing): 값 형식 데이터를 오브젝트(참조 형식)로 변환하여 힙에 저장하는 과정
- 언박싱(Unboxing): 힙에 저장된 오브젝트 데이터를 다시 값 형식으로 꺼내는 과정

| 과정 | 설명 | 예시 코드 | 
|------|------|-----------|
| 박싱 | 값 형식을 오브젝트에 담아 힙에 올림 | <mark>object a = 20;</mark> | 
| 언박싱 | 오브젝트에서 값 형식으로 변환하여 꺼냄 | <mark>int b = (int)a;</mark> |

- 박싱은 값 형식 데이터를 힙에 올려서 수명 조절이 가능하도록 함
- 힙에 올린 데이터는 가비지 컬렉터가 관리하므로 수명 연장이 가능
- 박싱/언박싱은 성능에 영향을 줄 수 있으므로 필요에 따라 사용

## 기본 데이터 형식과 복합 데이터 형식
| 구분 | 설명 | 주요 형식 |
|------|------|-----------|
| 기본 데이터 형식 | C#이 기본 제공하는 데이터 유형 | 정수형(int, short, byte), 부동소수점(float, double), 논리형(bool), 문자형(char), 오브젝트(object) |
| 복합 데이터 형식 | 기본 데이터 형식을 조합하여 새로 만든 데이터 유형 | 클래스(class), 구조체(struct), 튜플(tuple) | 

- 복합 데이터 형식은 기본 데이터 형식을 바탕으로 만들어지며, 복잡한 데이터 구조를 표현
- 기본 데이터 형식 이해가 복합 데이터 형식 학습의 기초가 됨

## 상수(const)와 열거형(enum)
- 상수(const): 변경 불가능한 값, 최초 선언 시 초기화 필요
  - <mark>const</mark> 키워드로 선언
  - 변경 시 컴파일러가 에러 발생
- 열겨형(enum): 여러 상수를 하나의 이름으로 묶은 데이터 형식
  - <mark>enum</mark> 키워드 사용
  - 값은 자동으로 0부터 순차적으로 할당 (중복 방지)
  - 사용 예: 사용자 응답 상태 (Yes, No, Cancel, OK 등)

| 특징 | 상수(const) | 열거형(enum) |
|------|-------------|--------------|
| 선언 키워드 | <mark>const</mark> | <mark>enum</mark> | 
| 값 변경 | 불가 | 각각의 이름에 고유 값 자동 부여 |
| 용도 | 단일 불변 값 | 관련된 여러 상수 값 집합화 |
| 오류 방지 | 변경 시 컴파일러 에러 | 중복 값 할당 방지 |

- 열거형은 상수 집합 선언 시 프로그래머 실수를 방지하는 데 유리하다

## var 키워드와 형식 추론
- var: 지역 변수 선언 시 컴파일러가 초기값을 보고 변수의 데이터 형식을 자동으로 추론하는 키워드
- 특징
  - 지역 변수에만 사용 가능 (메소드 내부)
  - 선언 시 초기값이 있어야 함 (형식 추론 가능)
  - 코드 간결화 및 가독성 향상

| 예시 코드 | 설명 |
|-----------|------|
| <mark>var a = 3;</mark> | <mark>a</mark>는 컴파일러가 <mark>int</mark>로 추론 |
| <mark>var b = "hello";</mark> | <mark>b</mark>는 컴파일러가 <mark>string</mark>으로 추론 |

- 클래스나 구조체 필드 선언에는 사용 불가
- 형식 추론은 컴파일 타임에 결정됨

## 요약표: 메모리와 데이터 형식 주요 개념
| 개념 | 설명 | 특징 및 역할 |
|------|------|--------------|
| 스택 | LIFO 구조, 기본 데이터 직접 저장 | 자동 메모리 관리, 함수 호출 시 생성/소멸 |
| 힙 | 자유 구조, 참조형 데이터 저장 | 가비지 컬렉터가 메모리 관리 |
| 값 형식 | 스택에 값 직접 저장 | 크기 작고 단순 데이터에 적합 |
| 참조 형식 | 힙에 값 저장, 스택에는 주소 저장 | 복잡하거나 큰 데이터 유형에 적합 | 
| 박싱/언박싱 | 값 형식 <-> 참조 형식 변환 | 힙 메모리 활용과 수명 조절 목적 |
| 상수(const) | 변경 불가 값 선언 | 코드 안정성 확보, 컴파일러 에러로 변경 방지 |
| 열거형(enum) | 여러 상수를 이름으로 묶음 | 상수 집합 관리 및 중복 값 방지 |
| var | 컴파일러가 변수 형식 자동 추론 | 코드 간결화, 지역 변수 선언에 한함 |

데이터 형식과 메모리 구조는 값 저장과 참조 저장의 차이에 따라 CPU 명령어, 메모리 관리, 그리고 프로그램 실행 효율성에 직접적인 영향을 준다. 스택과 힙의 구분은 메모리 할당과 해제 방식, 데이터 수명에 결정적이며, 박싱과 언박싱은 값 형식과 참조 형식 간의 상호작용을 가능하게 하여 C#의 메모리 관리 방식을 유연하게 만든다. 상수와 열거형은 코드의 안정성과 오류 방지를 돕고, var 키워드는 컴파일러의 형식 추론 능력을 활용해 코드의 가독성과 작성 효율을 높인다.

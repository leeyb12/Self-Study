## 프로그래밍과 프로그래밍 언어의 개념
> "프로그래밍은 컴퓨터에서 동작하는 프로그램을 만드는 일이며, 프로그래밍 언어는 프로그래밍을 위한 인공 언어이다."
- 프로그래밍: 컴퓨터가 수행할 명령을 작성하는 과정
- 프로그래밍 언어: 사람이 이해하고 작성할 수 있도록 설계된 인공 언어로, 컴퓨터 명령어 집합과 문법 체계를 포함
- 프로그래밍 언어는 자연어가 아닌, 컴퓨터가 이해할 수 있는 명령어 및 문법을 직접 설계한 것

## 최초의 컴퓨터와 프로그래밍 방법
- 세계 최초 컴퓨터: 애니악(ENIAC, Electronic Numerical Integrator and Computer)
  - 1943년 개발, 2차 세계대전 중 미군의 탄도 계산 수단으로 제작
  - 프로그래밍 방식: 하드웨어 유닛 간 배선을 연결하여 프로그램 구성
    - 유닛 예: 누산기, 함수 테이블 등
- 애니악의 프로그래밍은 물리적인 배선 연결로 매우 복잡하고 비효율적
- 2차 대전 이후 민간 및 과학 기술 분야에서 컴퓨터와 프로그램 수요 증가

## 컴파일러의 등장과 프로그래밍 언어 발전
- 기계어는 0과 1로 이루어진 이진 코드로 사람이 읽기 어려움
- 컴파일러: 사람이 읽기 쉬운 프로그래밍 언어 코드를 기계어(이진 코드)로 변환하는 번역기 역할
- 초기 컴파일러를 통해 사람이 이해하기 쉬운 언어(예: 어셈블리어)를 사용 가능
- 어셈블리어 예시: <mark>MOV EAX, 01</mark> (ex. 레지스터에 1을 적재)
  - CPU 내부에는 여러 유닛과 레지스터(임시 메모리 공간)가 존재하며, 계산에 사용
- 어셈블리어도 읽기 쉬운 편이지만 여전히 학습과 이해가 필요
| 구분 | 특징 |
|------|------|
| 기계어 | 0과 1로 구성, 컴퓨터만 이해 가능 |
| 어셈블리어 | 사람이 읽을 수 있는 코드, CPU 명령어에 가까움 |

## 고급 프로그래밍 언어의 등장과 발전 
- 존 베커스가 개발한 포트란(Fortran)은 프로그래밍 패러다임을 바꾼 대표적 언어
- 이후 베이직(BASIC) 언어 등장
  - 초등학생도 코딩 가능하도록 설계됨
  - 빌 게이츠가 초등학교 때 베이직으로 코딩 시작
- 최근에는 시각적 프로그래밍 언어인 스크래치가 초등학생 교육에 활용

## 운영체제와 C언어의 역사
- 유닉스(Unix) 운영체제
  - 데니스 리치와 켄 톰슨이 개발
  - PDP-11 하드웨어에 맞춰 먼저 어셈블리어로 개발 후 C언어로 재작성
- C언어 개발
  - 유닉스 개발 중 새로운 언어 필요성에서 탄생
  - B언어의 계승 버전으로 이름 붙음
  - 운영체제와 언어가 긴밀한 관계로 함께 발전
- UC 버클리에서 유닉스와 C언어 보급 확대 -> 사실상의 표준
- 1990년대까지 프로그래밍과 C언어는 거의 동의어 수준

## C++의 등장과 특징
- C++ 개발자: 비야네 스트로스트룹 (벨연구소 출신)
- 이름의 의미: C언어에 "1 더하기" (증가 연산자 ++) 한 것처럼, 기존 C언어에 객체지향 프로그래밍 개념 추가
- C언어 문법과 호환 가능 -> 기존 C 프로그래머가 쉽게 전환 가능
- 성능과 생산성을 동시에 추구

## C언어 및 C++의 한계와 문제점
| 문제점 | 설명 |
|--------|------|
| 메모리 관리 어려움 | 프로그래머가 직접 메모리 할당과 해제(메모리 누수 위험) 관리해야 함 |
| 플랫폼 이식성 문제 | 유닉스에 특화된 코드가 많아 다른 OS(맥 등)로의 이식 어려움 |
| 라이브러리 일관성 부족 | API가 일관적이지 않아 새로운 영역 학습 시 어려움 |
- 메모리 관리: 프로그램 실행 시 메모리 할당 -> 사용 후 반드시 해제해야 하는데 누락 시 메모리 부족 현상 발생
- 운영체제가 메모리 부족 프로그램을 중단시킬 수 있음
- 프로그래머 실수로 인한 메모리 누수 문제 빈번

## C#과 닷넷의 혁신
- **C#**은 C언어와 C++의 문제점을 개선하고자 등장
- 가비지 컬렉터(garbage collector) 도입으로 메모리 해제 자동화 -> 메모리 누수 문제 완화
- 플랫폼 이식성 문제 해결: **CLR(Common Language Runtime)**이 운영체제별 환경 차이 처리
  - 윈도우, 리눅스, 맥, 안드로이드, iOS 등 다양한 OS에서 작동 가능
- 닷넷 클래스 라이브러리의 일관성 덕분에 다양한 분야의 프로그래밍 적용 용이
- C# 사용 영역
  - 게임 개발(유닉스 스크립트)
  - 고성능 서버 애플리케이션
  - 데스크탑 애플리케이션 (포스 기기 등)
  - 웹 서비스(ASP.NET)
  - 클라우드 앱, AI, IoT 앱 개발

| 특징 | 설명 |
|------|------|
| 메모리 관리 | 가비지 컬렉터가 자동 해제 담당, 프로그래머 부담 감소 |
| 플랫폼 이식성 | CLR이 OS 차이 처리, 프로그래머는 어플리케이션 코드 작성에 집중 |
| 라이브러리 일관성 | 닷넷 클래스 라이블러리가 일관성을 제공하여 학습과 전환 용이 |
| 활용 분야 | 게임, 서버, 데스크탑, 웹, 클라우드, AI, IoT 등 광범위 |

## 프로그래밍 학습 및 실습 준비 
- 앞으로 강의에서는 C# 시작코드를 직접 작성해 봄
- 실습 도구로는 비주얼 스튜디오(Visual Studio) 설치
- 프로그래밍의 기초 개념과 역사부터 차근차근 이해 후 실습 진행

## 프로그래밍 언어 발전 흐름 요약
| 시기 | 주요 사건 및 특징 |
|------|-------------------|
| 1940년대 | 애니악: 배선 연결 방식 프로그래밍 |
| 1950~60년대 | 컴파일러 개발, 어셈블리어 등장 |
| 1960~70년대 | 포트란, 베이직과 같은 고급 언어 등장 |
| 1970년대 | 유닉스 개발, C언어 탄생 |
| 1980년대 | C++ 개발, 객체지향 프로그래밍 도입 |  
| 1990년대~현재 | C# 및 닷넷 등장, 가비지 컬렉터, 플랫폼 독립적 개발 환경 구축 |

프로그래밍 언어의 발전은 인간과 컴퓨터 사이의 소통을 점점 더 편리하게 하며, 하드웨어 제약과 운영체제 차이를 추상화하여 개발자의 생산성과 효율성을 극대화한다. 메모리 관리, 플랫폼 이식성, 라이브러리 일관성 개선은 프로그래밍 패러다임 변화를 이끌며, C#과 닷넷 환경은 현대 소프트웨어 개발에서 다양한 분야의 요구를 충족시키는 핵심 인프라로 자리잡았다.
